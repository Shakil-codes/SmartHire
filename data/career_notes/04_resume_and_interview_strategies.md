# Career Guide: High-Impact Resume Writing and Interview Strategies

## 1. The Anatomy of an ATS-Friendly Resume
Applicant Tracking Systems (ATS) scan resumes for keywords, formatting clarity, and role alignment. To maximize interview callbacks:
- **Clean Format**: Use single-column layouts, standard section headers (Experience, Skills, Education, Projects), standard fonts, and avoid images, graphics, tables, or complex column text boxes that confuse parsers.
- **File Format**: Standard PDF or DOCX formats with selectable, parseable text.

## 2. Crafting Bullet Points with the XYZ / STAR Formula
Never list passive job responsibilities (e.g., *"Responsible for writing code"*). Instead, apply Google's XYZ formula:
> **"Accomplished [X] as measured by [Y], by doing [Z]"**

### Examples of Weak vs Strong Bullet Points:
- **Weak**: "Worked on improving model accuracy."
- **Strong**: "Optimized deep learning recommendation model using hyperparameter tuning and feature selection, increasing ROC-AUC from 0.76 to 0.88 and boosting click-through rate by 14%."
- **Weak**: "Created REST APIs in Python."
- **Strong**: "Architected 12 asynchronous REST microservices using FastAPI and Redis caching, reducing average API response latency by 45% under 10k peak RPM."

## 3. Highlighting Technical Skills Effectively
- Group skills logically: Languages, Frameworks, Cloud & DevOps, Databases, Tools & Platforms.
- Avoid arbitrary rating bars (e.g., *"Python 90%"*). If a skill is listed, be prepared to discuss its internal mechanics, trade-offs, and failure modes in a technical interview.

## 4. Behavioral and Technical Interview Preparation
- Structure behavioral answers using the **STAR Method** (Situation, Task, Action, Result), dedicating 70% of your time to Action and Result.
- For technical screens: practice active problem communication, clarify edge cases before coding, analyze time and space complexity ($O(n)$ analysis), and test code with example inputs.
